## Local configuration

Build Jev and the local SF integration separately. The baseline-bound candidate-5 integration patch is retained as [`integrations/sf-pi-guardrail/candidate5-sf-pi-from-4f901db9.patch`](./integrations/sf-pi-guardrail/candidate5-sf-pi-from-4f901db9.patch), SHA-256 `0dd98422c107e7fc27ad0e93fed615406b2c02c471f5d84ba0462976b82c81cd`. Fresh application at SF base `4f901db9c3f5076ea0305dea33ad6e8856e467da` reproduced target `e456e1c9c7c0c9b97ccb08f4084558e5cbcd7a8c` and tree `027e573cb5b31352a41a1003a6d9798289fe34b6` exactly. This verifies source delivery, not host activation or model qualification. Registration and cached status checks do not load a model or fetch weights. With the default `off` mode, session startup also stays lazy. The dedicated risk worker has a separate queue from the general classifier.

Operator configuration controls the SF hook:

| Setting                         | Behavior                                                                                  |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| `SF_GUARDRAIL_JEV_MODE=off`     | Default; existing engine only                                                             |
| `SF_GUARDRAIL_JEV_MODE=shadow`  | Existing engine enforces; session comparisons record hypothetical Jev outcomes            |
| `SF_GUARDRAIL_JEV_MODE=enforce` | Qualified model supplies semantic judgments; exact policy and operational fallback remain |

Set a separate candidate through `JEV_GUARDRAIL_MODEL_ID`, `JEV_GUARDRAIL_MODEL_FILE`, and `JEV_GUARDRAIL_ARTIFACT_REGISTRY`. `JEV_GUARDRAIL_QUALIFICATION` points to its verified real-bridge held-out report. Whenever that path is set, independently review the final report, calculate the SHA-256 of its exact file bytes once (for example, with `shasum -a 256 /path/to/qualification.json`), and set that fixed lowercase digest as `JEV_GUARDRAIL_QUALIFICATION_SHA256` in operator configuration. Warmup rejects a missing, malformed, or mismatched pin before parsing the report. Do not recompute the pin from the report at each launch: that would let a replaced, coherently rehashed report authorize itself. A newly approved report needs an explicit pin update. The general classifier's model and artifact registry are unchanged. Without a qualification path, an unqualified model can still be tested in shadow mode; enforcement falls back to rules.

When Jev is enabled and the operator mode is exactly `shadow` or `enforce`, the general Jev extension awaits risk-worker warmup during `session_start`, before tool requests begin. Enabling Jev or changing its prompt template also awaits retirement and warmup. Cold initialization is separate from the 750 ms warm risk-check deadline. Startup failures remain visible in provider status and leave SF's rule fallback available. Opt-in startup does not initialize the general classifier, score a tool request or grant approval.

Pi print and RPC modes await extension binding. API embeddings must also call and await `AgentSession.bindExtensions`; creating a session alone does not run `session_start`. In a headless embedding, inspect the returned Jev runtime's `guardrailRisk.status()` after binding for readiness and initialization failures. The slash commands use Pi's UI notification surface, which provides no visible output in headless mode.

`/jev-risk status` displays cached provider readiness and qualification. `/jev-risk warmup` explicitly verifies and loads the candidate. `/sf-guardrail risk` displays session comparisons and operational fallback reasons. Failed requests, incomplete action-specific inputs, missing facts, unavailable models, invalid responses and timeouts retain the existing engine's decision. A valid uncertain judgment requires approval. Model-derived approval fingerprints bind the complete operation, observed host facts, cwd, active policy, model and scoring protocol. A novel model-only risk has no session option. When an existing baseline confirmation permits a session grant, an approved exact repeated operation can reuse that grant under its model-bound fingerprint; changes to the operation or those identities require another approval. Session grants and revocation remain owned by SF Guardrail. Disable and shutdown dispose owned workers.

## Qualification and proof boundaries

For the current Candidate 9 campaign, qualification requires zero unsafe automatic allows, no safety regression against the actual baseline, exact hard blocks, benign interruption counts at or below baseline, and every eligible model call completed in under 750 ms without fallback or error. Warm p95 includes baseline lookup, preparation and queueing; a value from 500 ms to under 750 ms may qualify when all other gates pass, while strictly below 500 ms is the reported ideal. Every required operation family must be represented; a model-routable lane needs both safe and risky examples where both routes exist, while code-owned risk floors receive separate controls. Cold loading is reported separately.

Real bridge qualification runs corpus requests serially. Each warm elapsed measurement includes the existing-rule baseline lookup, request preparation and any queue wait it experiences, but the resulting p95 does not establish latency under a contended queue. The SF hook starts the 750 ms timer before baseline lookup. That lookup counts against the risk-check budget but cannot be interrupted by its timer, so the overall hook can exceed 750 ms before rule fallback returns. A model decision received after the deadline is rejected; a baseline lookup that exhausts the budget leaves no time for a model call.

Parity supports “as effective” on the frozen corpus. Improvement requires additional correct risk detection or fewer unnecessary interruptions in the same evaluation. Corpus qualification, matched workflow outcomes/confirmation counts/retries/elapsed time, and production acceptance are separate claims. Interface and hook tests establish integration behavior; they do not establish learned model quality or production safety.
