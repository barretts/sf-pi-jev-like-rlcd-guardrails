# Candidate 7 blind operation-policy corpus

This directory contains newly authored, synthetic, **non-executed** source tool requests for a Guardrail risk qualification campaign. Labels are independent operation-policy targets under `fixtures/guardrail/RUBRIC.md` version 2. They do not come from an existing Guardrail rule decision, model prediction, or scored report. A human policy review is still needed before qualification.

- `valid.json` is the candidate-selection split.
- `test.json` is the held-out split. Keep its case bodies and labels closed until a candidate's weights, scoring protocol, cutoff, host projection, and gates are committed and frozen.
- `case.schema.json` records the case envelope; `manifest.json` pins the byte hashes and split metadata.

Each case has a source `operation.tool` and complete `operation.input`, an independently authored mock `fixture`, and an `expected` policy outcome. `fixture.observations` records mock org or browser facts separately from the request. A browser page snapshot is synthetic; its SHA-256 binds the fresh ref to that fixture, but it is not evidence of a real browser session. `fixture.policyBehaviors` is a symbolic exact-path policy map that must be installed as host configuration before replay. Gold labels and these policy outcomes must not be inserted into the model request. The risk-input projection is `{version:2, toolName, input, facts}` as defined in `src/guardrail.ts`.

Related variants are grouped before splitting. VALID and TEST use separate group and template IDs and no identical raw tool/input pairs. TEST labels and its group/template names are omitted from the manifest; the opaque SHA-256 permits a prefreeze verifier to pin the committed bytes without opening the holdout. Only VALID may guide candidate selection. No request in this corpus was executed against Salesforce, Slack, a browser, or a shell.

The final SF Pi host commit and its projection are pending. Source request completeness and model eligibility must be rechecked against that host before any replay; this corpus does not encode a final eligibility verdict. In particular, stale or missing browser click refs require host fallback, the canonical `data360_api` envelope may need mapping to the host's Data 360 tool, and `agentscript_preview` is a separate source tool that current Jev v2 family routing does not accept. The native preview rows are policy fixtures until the host supplies a versioned contract. Direct bash `sf agent preview send` rows are labeled conservatively because a claimed earlier CLI start, shell output, or PATH cannot attest to a Pi-owned Mock session. A host-owned preview start and attested session would be a separate fact path; it is not inferred from those CLI requests.

Authoring consulted only the local operation-policy rubric, the Jev v2 host input validator, source tool schemas, and the following primary API references for syntax: [Salesforce agent preview send](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_agent_preview_send.html), [Salesforce org assign permset](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_org_assign_permset.html), [Slack canvases.access.set](https://docs.slack.dev/reference/methods/canvases.access.set/), and [Slack canvases.delete](https://docs.slack.dev/reference/methods/canvases.delete/). No Candidate 6 VALID or TEST case bodies, per-case model predictions, or scored report files, and no Candidate 7 TRAIN proposals were read by the author. While locating the contract, a broad search displayed aggregate Candidate 6 results in `GUARDRAIL.md` prose; those aggregates did not inform case selection or labels. The retained SF Pi integration patch and current tool schemas were used only to shape request fields and may differ from the pending final host.

A separate read-only audit compared preseal drafts against 52 Candidate 7 TRAIN cases and 175 Candidate 6 admitted TRAIN rows without sending their case bodies or labels to the corpus author. It found no identical IDs, group IDs, or raw tool/input pairs, but identified 14 groups with close action or effect-template patterns. The author revised the closest record-update, executed permission-heredoc, tree-import, and Canvas write-grant patterns before sealing. Broad family-level safe-read versus risky-write patterns remain and limit any claim that this holdout tests wholly unfamiliar effects. The audit did not inspect model predictions or scored reports.

The per-split coverage files count static source requests by provisional Jev v2 input lane, exact host-policy lane, unsupported native-preview lane, and pre-model fact fallback. The counts are not host execution receipts or model eligibility decisions. Fresh browser click cases have matching synthetic page/ref hashes and provisional v2 input coverage, but qualification still requires the final host to prove that the observed ref denotes the committed effect. Browser press cases lack a focus fact, so their conservative confirm labels test uncertainty rather than a known focused control.

Before any Candidate 7 validation score, VALID cases `c7-valid-007` through `c7-valid-009` were corrected from shell redirections to source `write` requests with `path` and `content`. The SF Pi host treats a bash request as a shell-command subject, so a bash redirection cannot exercise the fixture's exact `file:` policy. The three labels and exact-policy lane are unchanged; the corrected requests let the host apply the authored block, confirm, and off path behaviors. This correction changed the VALID bytes and manifest hash only. The held-out TEST bytes, labels, and hash were neither opened nor changed during the correction, and no model score was run.

A later fake-host preflight found that VALID case `c7-valid-031` requested `@e71` from a snapshot containing only `@e72`; the host correctly classified that as a missing ref. Before scoring, its captured snapshot was corrected to include `@e71`, with a recomputed snapshot hash and an explicit fact that the capture aged out before the click. Case `c7-valid-032` remains the missing-ref contrast. The approval label and stale-ref reason for case 031 remain unchanged. This correction again changed only VALID and its manifest hash; TEST stayed closed and no model score was run by the corpus author.
